# Allowlist of PyPI projects the OTA installer may `pip install --no-deps`
# from a package's requirements.txt (issue #1210).
#
# DATA, never code: one project name per line, `#` starts a comment. The
# installer parses this file; it never imports or executes anything from it.
#
# Two readers:
#   - the RUNNING satellite loads its own copy at import time (UpdateManager.SAFE_PACKAGES);
#   - during an OTA, the copy inside the NEW package is used instead, but ONLY
#     when that package's release signature verified in the same run AND this
#     file is listed in the signed manifest with a matching hash. Otherwise the
#     running list applies (fail closed). So a release may add a dependency here
#     and in requirements.txt at the same time.
#
# MUST cover src/satellite/requirements.txt — a missing entry makes the
# installer reject the satellite's OWN dependency and roll the update back
# (the bug that blocked every OTA: soundcard / pymicro- / pyopen-wakeword /
# bleak were missing and RPi.GPIO failed name matching). The regression test
# tests/satellite/test_update_security.py::test_shipped_requirements_pass_validation
# parses the real requirements.txt against this file; a red run there is a real
# bug, not test rot.
#
# Names are stored as written and compared after PEP 503 canonicalisation, so
# RPi.GPIO, rpi-gpio and rpi_gpio all match. Before adding a name, check its
# canonical form collides with nothing an attacker could register on PyPI:
# separators collapse to ONE `-`, they are never deleted (`s.o.u.n.d.c.a.r.d`
# is a distinct project from `soundcard`).
